When a code checker says "no issues found", how far can you trust it?

A "no issues found" (CLEAN) result is only true for what was actually checked: the build settings and the kinds of input that were run. Six small C examples show this with three free checkers and AddressSanitizer, with measured coverage.

FAQ

Does "no issues found" from a static analyzer mean my code is safe?

No. In examples 02 and 03, clang --analyze, gcc -fanalyzer and cppcheck report nothing, yet the code crashes on one kind of input.

Does the clang static analyzer catch off-by-one errors?

Not in example 02 (clang 18.1.3): a <= loop writes one element past a stack buffer and nothing is reported. AddressSanitizer catches it on the boundary input.

Is running the code with AddressSanitizer enough?

No. In example 05 the tests never reach the line that causes the bug, so AddressSanitizer reports nothing, while gcc -fanalyzer and cppcheck find it.

What is the difference between line coverage and testing the risky case?

A line can run many times without the dangerous condition ever happening. In example 02 the buggy line runs 9 times on normal input; the bug needs a count equal to the buffer size.

How should I report a static analysis or AI code review result?

With its scope: build settings, kinds of input tried, how deep the testing went, and whether the test was shown able to fail. The standard defines a short format.
